# Skills Registry — guide for agents

A self-hosted skills registry (TypeScript, modular monolith following DDD, Postgres + pgvector, MCP). Spec: `docs/superpowers/specs/2026-10-28-skills-service-design.md`. Decisions: `docs/adr/`.

Code, comments, docs and commit messages are in English.

## Layers inside a module (spec §8.3)

```
interfaces      → MCP tools, HTTP routes, zod input validation
application     → use cases and queries; declares ports (repositories, BlobStore, Embedder, Clock, EventPublisher)
domain          → aggregates, value objects, events, invariants. Plain TypeScript, no dependencies
infrastructure  → port implementations: Postgres repositories, blob, embedder, outbox
```

Rules (checked automatically — `pnpm arch`, dependency-cruiser):

- `domain` imports nothing outside its own `domain` (except the dependency-free `shared-kernel`; from npm — only `yaml`, for parsing frontmatter).
- `application` imports only its own module's `domain` (plus `shared-kernel`, another module's public `index.ts`, and npm `zod` and `diff`).
- Modules talk to each other only through a module's public `index.ts` or through domain events. Importing another module's internals is forbidden.
- `infrastructure` and `interfaces` are not imported from `domain` or `application`.
- `packages/cli` does not import `apps/*` (rule `cli-no-apps`): it talks to the server only over HTTP; shared types come from `@skills/contracts`. Effects (network, output, env) go through `CliEnv`; tests use `test/fake-env.ts` and the fake GitHub in `test/tarball.ts`.
- Each module owns its DB schema (`catalog.*`, `search.*`, `identity.*`); other modules' tables are never read directly. Cross-cutting concerns live in the `platform` schema (outbox, audit, migrations).

Layout: `apps/server/src/modules/{catalog,search,identity}/{domain,application,infrastructure,interfaces}`, `apps/server/src/shared-kernel` (Result, errors, events, Clock, the AuditLog port), `apps/server/src/platform` (composition), `packages/contracts` (REST zod schemas), `packages/cli` (the `skills-registry` client CLI: import from GitHub, `update`, `install`; spec `docs/superpowers/specs/2026-10-29-client-cli-design.md`).

## Domain glossary

- **Skill** — aggregate: `slug`, `status` (`active` | `archived`), `currentVersion`.
- **SkillVersion** — an immutable version of a skill: number, `name`, `description`, manifest, author, message, `restoredFrom?`.
- **Manifest** — the version's file manifest: path → sha256 and size; must contain `SKILL.md` with frontmatter.
- **Slug** — unique kebab-case skill identifier; matches `name` in the frontmatter.
- **Blob** — file content addressed by sha256 (the `BlobStore` port).
- **Principal** — an authenticated subject (a user or a token owner), the result of checking a token/session.
- **ApiToken** — an `sk_…` token; only its SHA-256 is stored in the DB; has `lastUsedAt`/`revokedAt`.
- **Outbox** — a table of events written in the same transaction as the change; a worker delivers them to subscribers (Search).
- **Sign-in method** — `password` or `sso`, chosen by configuration: all of `OIDC_ISSUER`/`OIDC_CLIENT_ID`/`OIDC_CLIENT_SECRET` set → the web UI signs in only via OIDC (`GET /api/auth/config`); API tokens work in both modes (ADR 0009).
- **`oidc_sub`** — the provider's subject on a user (unique, null = not linked). A first SSO sign-in with an unknown `sub` creates a user; an existing user is linked only explicitly with the server CLI `link-sso <login> <sub>` / `unlink-sso <login>`, never by name or email. Role is re-synced from groups on every SSO sign-in.

## How to add a use case

1. Domain test first (`*.test.ts` next to the code): aggregate/value object invariants — red → green.
2. Use case in `application/`, tested with fake ports (no DB); ports are declared there too.
3. Port adapter in `infrastructure/` (Postgres, etc.).
4. Integration test `apps/server/test/**/*.int.test.ts` (Testcontainers, real Postgres).
5. Wire it into `interfaces/` (route/MCP tool) and into the `platform/` composition.

## Web UI (`apps/web`)

SPA on React 19 + Vite (via Vite+), served by the same server. UI kit — **shadcn/ui on Base UI**; Radix is forbidden (rule `no-radix` in dependency-cruiser plus a `pnpm-lock.yaml` check in `pnpm arch`).

Layout:

- `src/main.tsx` — root: `QueryClientProvider`, router, `<Toaster />` (`src/components/Toaster.tsx`); `src/app/` — shell and routes.
- `src/api/client.ts` — typed client: `api.get/post/put/delete/upload`; responses are validated with `@skills/contracts` schemas, errors are `ApiError` (`src/api/errors.ts`), 401 → `onUnauthorized` subscribers; `filePath(slug, path)` encodes a file path segment by segment. `src/api` does not import components.
- `src/components/ui/` — generated by the shadcn CLI and committed, not formatted by `vp fmt`. New component: from `apps/web` — `pnpm dlx shadcn@4.23.0 add <name>` (in pnpm 11 `pnpm --filter … dlx` does not work). Edit a generated file only with a `// changed: <why>` comment. Base UI components take `render={<Link …/>}`, not `asChild`.
- Custom components only where shadcn has no equivalent; Tailwind classes and `cn()` from `src/lib/utils.ts`, colors only via theme variables (`bg-background`, `text-muted-foreground`…). No separate CSS files except `src/styles/global.css`.
- All UI strings are in English, in `src/strings.ts`. Success — `notify.success(text)` from `src/lib/notify.ts` (toasts on Base UI Toast; there are also `notify.error` and `notify.dismissAll`, callable from anywhere, not only from components); form error — under the field; page error — `ErrorAlert`. `sonner` is not used: it inserts a `<style>`, which the CSP forbids.
- `web` does not import `apps/server` (rule `web-no-server`): shared types only via `@skills/contracts`.

Security: CSP `default-src 'self'` — no external requests from the browser (fonts, icons and styles come only from the bundle), no inline scripts and no inline `<style>`: the tree is wrapped in `<CSPProvider disableStyleElements>` from `@base-ui/react/csp-provider` (in `main.tsx` and `renderWithApp`), and the rules Base UI would insert as `<style>` (`.base-ui-disable-scrollbar`) live statically in `global.css`. The CSP is strict (`style-src 'self'`, no `style-src-elem` and no hashes): a new dependency that inserts `<style>` breaks `e2e/csp.spec.ts` — configure it (provider, shadow root, static CSS) instead of loosening the policy (ADR 0006). Skill Markdown is untrusted input: `react-markdown` + `rehype-sanitize` (default schema), no `rehype-raw`, links only `http:`, `https:`, `mailto:` and relative. Mutations — `fetch` with `credentials: 'same-origin'` (the server checks `Origin`).

How to add a page: component in `src/<section>/XxxPage.tsx`, strings in `strings.ts`, data via `api` and TanStack Query, route in `src/app/routes.tsx` (replace the `soon` placeholder); a test next to it (`XxxPage.test.tsx`) renders via `renderWithApp(ui, { route, me })` from `test/setup.ts` (QueryClient without retries, memory data router — `useBlocker` works, `<Toaster />`: toasts live in its provider and disappear on `cleanup()`, no separate reset needed; `ui` is an element or a route table, e.g. `routes` from `src/app/routes.tsx`; returns `router`, the current location is `router.state.location`); network — msw (`test/msw/handlers.ts`, `server.use(...)`; an unhandled request fails the test). In jsdom the file name in multipart is lost (it arrives as `blob`) — assert field names and content instead.

Running: `pnpm dev:web` (Vite, proxies `/api` and `/mcp` to `localhost:3000`), `pnpm build:web` → `apps/web/dist`. Web tests are the `web` project in `vp test` (jsdom).

## Commands

`pnpm check` (vp check: lint, format, types), `pnpm arch` (dependency-cruiser + Radix ban in the lockfile), `pnpm knip`, `pnpm test` (unit + web + coverage ≥ 90% for domain/application), `pnpm test:int`, `pnpm build:web`, `pnpm build:cli` (→ `packages/cli/dist/cli.js`), `pnpm verify` (everything at once), `pnpm test:e2e` (Playwright against the built image via `scripts/e2e-image.sh`; a separate `e2e` job in CI).

**Run `pnpm verify` before finishing a task.** Do not disable linter rules or edit `.dependency-cruiser.cjs` to get around a violation: fix the code.

## Running locally

- Tests: `pnpm install`, then `pnpm verify`. Docker is required: integration tests start Postgres via Testcontainers. The test for the real embedding model is skipped unless `MODEL_DIR` points to the model (`node scripts/download-model.mjs <dir>`) or `ALLOW_MODEL_DOWNLOAD=1` is set.
- Server build: `pnpm build` (`vp pack`) produces `apps/server/dist/main.js` (HTTP server) and `dist/cli.js` (CLI). The server does not run from sources.
- The whole box: `cp .env.example .env`, fill in the secrets, `docker compose up -d`; check with `curl localhost:3000/healthz`. Token and connect command: `docker compose exec app node dist/cli.js create-token admin --name dev`. Details are in the README.
- End-to-end image check: `bash scripts/smoke.sh`. It is a separate compose project on port 38080 that removes its volume afterwards. It is also the second job in CI (`.github/workflows/ci.yml`).
